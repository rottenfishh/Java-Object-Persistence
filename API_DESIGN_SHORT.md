# Краткий дизайн API

## Назначение

API фреймворка предназначен для сериализации и десериализации Java-объектов в JSON с поддержкой:

- декларативной настройки через аннотации;
- вложенных объектов;
- циклических и shared-ссылок;
- ленивой загрузки полей;
- фильтрации JSON без полной загрузки данных в память.

## 1. Аннотационный API

Конфигурация модели задается декларативно:

- `@JsonSerializable` помечает класс как поддерживаемый фреймворком;
- `@JsonElement(name = "...")` задает имя поля в JSON;
- `@JsonIgnore` исключает поле из сериализации;
- `@JsonLazy` помечает поле для ленивой загрузки.

Идея такого API в том, что пользователь описывает правила сериализации прямо на уровне модели, без ручного написания преобразователей.

## 2. Основной mapper API

Для обычной работы используется фасад:

```java
JsonMapper mapper = new JsonMapper();
String json = mapper.toJson(obj);
MyClass restored = (MyClass) mapper.fromJson(json, MyClass.class);
```

Этот API скрывает внутреннюю работу с Jackson, reflection и метаданными, оставляя пользователю простой интерфейс из четырех основных операций:

- сериализация в строку;
- десериализация из строки;
- сериализация в файл;
- десериализация из файла.

## 3. API ленивой десериализации

Для объектов с тяжелыми вложенными полями используется отдельная точка входа:

```java
LazyJsonMapper mapper = new LazyJsonMapper();
User user = (User) mapper.fromJson(json, User.class);
```

Если поле помечено `@JsonLazy`, то при десериализации вместо готового объекта создается proxy. Реальное значение загружается только в момент первого обращения к полю.

Такой дизайн API уменьшает лишние затраты памяти и времени, если пользователю нужна только часть данных.

## 4. API поддержки графов объектов

Сериализация поддерживает не только деревья, но и графы объектов.

Для этого в JSON используются служебные поля:

- `@id` для первого появления объекта;
- `@ref` для повторной ссылки на уже сериализованный объект.

Это позволяет корректно работать с:

- циклическими ссылками;
- несколькими ссылками на один и тот же shared-объект.

## 5. API фильтрации

Фильтрация вынесена в отдельный слой API и состоит из трех частей:

- `Expression` для описания условий;
- `JsonIndexer` для построения индекса по JSON;
- `LazyFilter` для фильтрации объектов через ленивый доступ к полям.

Пример условия:

```java
Expression expr =
    new AND(
        new Equals("city", "Moscow"),
        new GreaterThan("age", 20.0)
    );
```

Пример ленивого фильтра:

```java
LazyObjectFilter<User> filter =
    user -> user.getAge() >= 18 && "Moscow".equals(user.getCity());
```

Такой API особенно полезен для больших JSON-файлов, когда нужно читать только те поля, которые реально участвуют в фильтрации.

## 6. Главные идеи дизайна

- API декларативный: правила задаются аннотациями.
- API фасадный: пользователь работает через `JsonMapper` и `LazyJsonMapper`.
- API разделяет eager и lazy режимы, не смешивая их в одном перегруженном интерфейсе.
- API фильтрации выделен в отдельный модуль для эффективной работы с большими JSON-данными.

## 7. Итоговая формулировка для презентации

Дизайн API фреймворка построен вокруг простой пользовательской модели: аннотации описывают контракт сериализации, `JsonMapper` и `LazyJsonMapper` предоставляют удобные точки входа, а отдельный filter API позволяет эффективно работать с большими JSON-структурами без полной материализации объектов в память.
